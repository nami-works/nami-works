Local Delivery — warehouse-method override (mockup v1)

Surfaces orders Shopify still classifies as SHIPPING (warehouse) so an operator can dispatch them via Local Delivery once their FulfillmentOrder has been moved to a store location in Shopify admin. v1 — rev to match the actual current LD page layout: Location select + warning badges + Orders-to-deliver status row, no Period/Promise/Limit (those moved to Settings). Single inline icon next to the order ID instead of a separate Method column.

Changes vs current

  • New "Include warehouse orders" toggle below the warning badges in the Route Manager section. Off by default; activates the dormant ?deliveryMethod=all plumbing.
  • New "Warehouse: N" badge in the badges row when warehouse-method orders exist at the selected location. Clickable when toggle is OFF (activates it); display-only when ON.
  • Warehouse-origin marker in the existing Due column. The Due column's bucket-driven badge (bolt = today, alert-triangle = overdue, clock = tomorrow, x-circle = failed) is replaced by the package Polaris icon for any row whose methodType !== "LOCAL". One column, dual semantic: due state for LOCAL rows, warehouse-origin marker for non-LOCAL rows. No new column.
  • Override confirmation modal opens on Dispatch when the route contains 1+ warehouse-method orders. Hybrid copy: short operator-friendly statement up top, Show technical details expander for the audit-tag + Shopify-state info.
  • Audit signals on confirm — Shopify tag ld_method-override + DB column LalamoveDispatchJob.methodOverride.

Rules locked from the plan

  • Toggle does NOT persist. Always resets to OFF on page load — forces a deliberate operator action.
  • FulfillmentOrder must already be at the local-delivery store before the order surfaces. Operator does the fulfillmentOrderMove in Shopify admin first.
  • Auto-cron stays strict LOCAL-only. The auto-delivery cron will NEVER pick up warehouse-method orders, even with the toggle on. Override is operator-only.
  • Mark-delivered path is untouched. Fulfillment is created at the FO's assigned location (which the operator moved).
  • Mobile (/app/local-delivery-mobile) is Phase 2. Desktop ships first.
