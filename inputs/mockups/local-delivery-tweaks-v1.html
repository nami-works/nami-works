Changes vs current

  • Fulfillment details block dissolved. Its only survivor (the Location selector) plus the warning stack move into Route manager — a single consolidated block in the aside. Start date, Delivery promise, and Same-day cutoff are dropped (server-side D-90 + per-location Settings reads).
  • Orders-to-deliver badge drops the "all" subtext in the all-locations case.
  • Two new bulk actions in Route manager menu: "Fetch quotes for all routes" and "Dispatch all routes". Disabled when no specific location selected. Dispatch auto-quotes missing routes inline.
  • Order states get two new buckets: 🚫 Failed (overrides everything) and 🚨 Overdue. Today emoji flips 📦 → ⏳.
  • Tabs → chips in the orders table, with a new Failed filter. Active chip is dark/filled; inactive are subdued grey for clear separation.
  • Column density: halved padding, no "at" in date, customer 15/10ch lock, Route compact "#NN" when collapsed, "—" instead of Unassigned badge, "Today" not "Due today", Unassign button.
  • Settings — Delivery details restructure:
    • Market / City row goes from 4-col with two empty cells → 3-col, timezone fills the third slot.
    • Divider above "Enable automatic delivery" removed entirely.
    • Delivery promise + Order cutoff time become regular settings fields (no longer children of the toggle); the toggle moves below them as a peer setting.
    • Divider above "Save delivery details" moves below the chevron and outside the collapsed conditional, so it stays visible as a section terminator when the block is collapsed.
    • Same divider treatment applied to the Retail goals section.

Open questions

  • Bulk action placement — currently shown inside the existing actions menu (alongside Auto assign / Clear all routes). Alternative: surface them as two prominent buttons next to the "47 orders to deliver" badge for one-click discoverability. Tradeoff: menu = tidy but less discoverable; standalone = more visible but adds visual weight to the header.
  • Failed badge tone — both Failed and Overdue use critical tone in this mockup, which makes them visually similar. Acceptable, or should Failed use a different tone (e.g. plain dark badge) to distinguish "operational failure" from "time-pressure"?
  • Route compact mode trigger — currently driven by !isFullscreen. Confirm: should the orders table use compact route labels whenever the page is in non-fullscreen mode, or only when an explicit narrow-viewport breakpoint hits?
  • Customer truncation char width — 15ch / 10ch is character-count truncation with "…". Names with diacritics (Lúcia, João) render fine but Asian/long Latin names may look identical when truncated. Acceptable trade for density?
