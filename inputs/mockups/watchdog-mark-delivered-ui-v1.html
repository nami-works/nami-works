Watchdog mark-as-delivered — UI surfaces

The watchdog cron will reconcile every terminal-status Lalamove dispatch into Shopify fulfillments using per-stop POD as the source of truth. Most routes auto-fulfill silently and disappear from the page (clean / mixed buckets). Some are flagged needs-review and require operator attention. This mockup covers every UI surface this change touches.

Locked decisions from session: (1) remove maps from BOTH Route details and Manage-route modals; (2) surface needs-review on the aside Route Manager card AND inside the modal; (3) banner copy = reason + plain-language hint, no literal CLI command.

1. Touchpoints overview

A. Aside Route Manager card
Per-route card in the right rail. Gains a status chip (Needs review · Held · Delivered) when bucketed.
B. Route details modal
Map removed. Banner surfaces on needs-review. Per-stop POD pills already exist.
C. Manage-route modal
Map removed. Pure table-only layout for unassigning orders.
D. Mobile parity
Same banner + chip pattern surfaces on /app/local-delivery-mobile.

2. Aside Route Manager card — all states

Three card variations are new. Today's pre-watchdog card has no per-stop bucket status — it shows active dispatch only. Once the watchdog is live, terminal-state routes either disappear (clean) or carry a chip indicating what happened. Operator scans the rail and only stops on the warning chips.

Notes / decisions captured

  • Map removal scope — both Route details AND Manage-route modals. Decided in session.
  • Aside surfacing — needs-review surfaces both on the card chip AND inside the modal banner (belt + suspenders).
  • Banner copy — plain language, no literal CLI command. Each reason gets its own banner title; the hint sentence is consistent ("Confirm with the team... then resolve from the CLI"). i18n strings: routeDetails.needsReview.<reasonKey>.title + .hint.
  • Suspect row treatment — 3px left rail in warning tone + light orange row background. The ? Suspect pill is a new POD pill state (alongside delivered / failed / pending / unknown). May map to existing unknown visually with different copy, TBC in implementation.
  • Card-fade for clean — opacity-55 + subdued chip for a brief reload window so the operator sees what got auto-handled instead of routes silently vanishing between page loads. Alternative: skip the fade and let routes disappear cleanly (less context, less code).
  • "Review" action on needs-review card is just a deep-link to the details modal — same code path as Details. The label change conveys urgency.
  • Mixed-bucket chip copy — "1 redelivery" reads better than "Partially delivered" because it names what the operator needs to do next (the failed order is back in tomorrow's queue).
  • Skip bucket (no deliveries at all) — treated as needs-review with a "No deliveries succeeded" reason. Not drawn separately; visually identical to needs-review with all stops showing failed/unknown.
  • i18n — all new copy goes into app/i18n/locales/en.json and pt-BR.json under routeManager.chip.* and routeDetails.needsReview.*.
