Trade-offs at a glance

  • A · current 50/50 stack — baseline. Map and table both visible. Pain: routes with 5+ stops cut the table to 2-3 visible rows. The screenshot Lucas posted is exactly this state.
  • B · table-dominant 35/65 stack — small change vs A: map shrinks to a thumb (still useful for spatial confirmation), table gets the breathing room. Cheapest fix; one CSS line. Closest to "see the orders, glance at the map" intent.
  • C · side-by-side — most info-dense. Map and table at full vertical height. Cost: needs ~900px modal width to look right; the embedded admin iframe is tight on smaller laptops; collapses to stacked on narrow screens (so you'd need a media-query branch). Best when the operator wants to inspect spatial + tabular together.
  • D · tabs — cleanest at any width: each view gets the full real estate. Cost: forces a click to switch context, hides one view by default. Works well if 90% of the time the operator only needs one of the two; less good if they bounce between map and rows constantly.
