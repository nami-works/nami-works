Local Delivery — backlog visual changes

One mockup covering all visual changes from inputs/backlog/local-delivery.md: badge standardization, per-route card restructure, polyline edit toolbar, address-errors modal rewire, and the "Shipment requests" removal. Plus three micro-fixes (sidebar parity in expanded mode, "Dispatching: 1/3" spacing, "Orders to deliver: n" format) covered in the Notes panel of each section.

Out of scope here: the canonical tag rename (ld_address_review → ld_address-confirm) is already on main from Track 1B1 — this mockup just consumes the new tag name in the address-errors modal deep-link.

1. Header badges — standardization

All badges adopt: <s-icon> + <s-badge tone="…"> + ": n" format (no parentheses). One badge removed entirely (Shipment requests). One newly visible on All locations (Potential address errors).

  • Potential address errors: <s-icon type="alert-triangle"> (unchanged from today), <s-badge tone="warning">, ": n". Newly visible when "All locations" is selected (today: hidden).
  • Shipment requests to process: REMOVED entire UI + computed logic. See section 6.
  • Orders to deliver: <s-icon type="receipt-dollar"> (suggestion — see open question below), <s-badge tone="info">, ": n".
  • "Dispatching: n/m": drop the spaces around the slash. Locale string change in en/local-delivery.json + pt-BR/local-delivery.json: "Dispatching: {{completed}} / {{total}}" → "Dispatching: {{completed}}/{{total}}".

3. Polyline edit toolbar — Edit / Confirm / Cancel

New toolbar overlay on the map block. Three states: default, editing (drag+drop unlocked, polylines dotted), and editing-with-confirm-pending. The toolbar lives at top-right of the map (does NOT overlap the existing fullscreen toggle that sits at top-left on desktop).

State A · default

Polylines rendered solid in their default colors.

State B · editing

Polylines dotted + subdued. Stops draggable. Edit button is hidden — replaced by Confirm + Cancel.

State C · after confirm

New polylines from API recompute (no TRAFFIC_AWARE per Track 1A). Previous polylines erased.
Spec details:
  • Default → Edit clicked: unlocks Google Maps drag + drop on stops; current polylines reformat as dotted (4px gap) and subdued (~50% lightness via lerp toward white); Edit hides; Confirm + Cancel appear.
  • Confirm clicked: calls existing Google Routes recompute path, renders new polylines in default solid format, erases previous polylines completely, restores Edit button.
  • Cancel clicked: reverts all stop drags since last auto-assignment or last Confirm; restores original polylines in default format; restores Edit button.
  • Toolbar position: position: absolute; top: 12px; right: 12px; on the map container.
  • Toolbar does NOT render when no routes are visible (avoid an editor for nothing).
  • While editing, the existing per-route cards stay interactive — but their primary action ("Request driver", "Cancel", etc.) is disabled until the user resolves the edit (Confirm or Cancel) so we don't dispatch a route mid-edit.

7. "Dispatch all" — bug fix (Track 1D, no visual change)

No visual change; behavioral fix.
Diagnostic from CloudWatch (today, 2026-05-05 16:19 BRT):
  • The /app/local-delivery.data loader returned 502 after 9.4s on a specific locationId=gid://shopify/Location/97784398144. Around the same window, the shop-ingest:reconcile background job logged elapsed=502.5s and elapsed=3502.8s. The 502 strongly correlates with reconcile holding the DB connection pool while the loader times out.
  • The dispatch-all handler at app.local-delivery.tsx:3552 looks structurally fine — quote-then-place sequential per route. The bug is upstream: the LOADER fails to revalidate after dispatch-all completes, so the UI shows stale state. With reconcile contention, the post-dispatch revalidator.revalidate() call at line 3614 sometimes returns 502.
  • Proposed fix (lands inside the UI sequential branch since same file): add error handling around the post-dispatch revalidate; if it 502s, log + retry once after 2s; surface a non-blocking banner if the second revalidate also fails. Don't let a stale loader block the user from seeing dispatched-route state.
  • Longer-term — investigate why shop-ingest:reconcile takes 500-3500s on this shop. Likely a Shopify pagination loop without a hard cap. Out of scope for this round; flag for a separate ticket.
