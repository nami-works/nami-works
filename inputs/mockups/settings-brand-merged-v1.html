IA decision — 3 options compared (PM analysis)

Option A — Inline full merge

Fold all tone-sources management directly into the Brand page. Brand becomes one very long page (~1700 lines of UI). Rejected: tone-sources has its own complex sub-UI (manual upload S3, re-extract Claude jobs, accept/reject hypotheses) that doesn't fit cleanly as a section. Page becomes unwieldy.

Option B — Sub-tabs inside Brand (Configuration / Tone sources / Learnings)

Brand gets a nested tab strip. Rejected: nested tabs inside an embedded admin tab strip violate Shopify's "tabs are secondary navigation only" rule (CLAUDE.md "Shopify Design Compliance > Information architecture"). Also visually noisy.

Option C — Surface tone-sources STATE inline, keep deep management at sub-route ✓ Recommended

The Brand page gains a "Tone of voice" block (the green-tinted block above) showing live counts + CTAs. The deep management sub-route stays at /app/settings/brand/tone-sources. From any entry point — Settings > Brand or Storytelling > Brief — the user sees tone-sources state and can navigate to it. The IA story is "Brand is the declared identity; tone-sources is the evidence base; both are visible from Brand".

Why C wins

  • Solves the discovery gap: the merchant who lands on /app/settings/brand now SEES that tone-sources exists. No more "only reachable via Storytelling".
  • Avoids file bloat: tone-sources stays at its current route. No 1700-line monolith.
  • Storytelling deep-links keep working: the Brand-context band on /app/storytelling/brief still links to /app/settings/brand AND /app/settings/brand/tone-sources; both targets still resolve.
  • State at-a-glance: the green summary block doubles as a sync indicator (synced N min ago) and a CTA cluster, so the merchant knows the AI's evidence base is healthy before generating a brief.

Implementation notes (r2 — for hand-off)

  • Drop back-action on Brand sub-route. Remove <s-button slot="back-action"> from app.settings_.brand.tsx. The Settings tab strip already provides nav back to Settings (clicking Locations/Providers/Carriers navigates to /app/settings). Removing the back-action band should also resolve the main-vs-aside Y misalignment because the back-action chrome was the band pushing main down while aside stayed pinned.
  • Move "Tone of voice" to aside slot. Wrap the existing green block with slot="aside" and put it AT THE TOP of the aside column (above Export + Learned from edits). It unlocks all AI writing — placement should reflect that importance.
  • "Manage sources" → primary Polaris button. Replace the custom outlined-link CTA with <s-button variant="primary">Manage sources</s-button>. The Link-to-tone-sources navigation moves inside the button's href. "Set manual override" stays as a secondary or tertiary button below it.
  • Folding Manual override INTO Brand configuration. The existing tone-of-voice text-area becomes a labeled field inside the brand-configuration block (relabeled "Tone of voice (manual override)"), so there's no longer a separate Manual-override block in main. Reduces main to one cohesive form.
  • Main+aside Y misalignment — root cause confirmed. Lucas (2026-05-12): "The misalignment is caused by the Tabs UI, which pushes main below, but does not touch aside. It should touch aside." So the fix is structural — the tabs row must occupy a row position that BOTH columns respect, not be a default-slot child that only main sees.

    Specifically, today's structure puts <PageTabs> as a default-slot child of <s-page> alongside the main <s-section>. Polaris's slot="aside" goes to a separate column region that doesn't see PageTabs in its document flow → aside starts at the TOP of body, main starts BELOW the tabs row, columns end up misaligned. The back-action band on Brand was a second, smaller contributor (now gone in r2) but the tabs misalignment exists on every off-block-tab page (Storytelling, Affiliates, Merchandising, Settings, Retail Sales).

    Fix options (need to pick one and validate live):
    • Option F1 — Aside spacer. Inject an invisible top-spacer in the aside slot matching PageTabs's rendered height (~44px = ~28px tab + 1px divider + 16px margin-bottom). Aside starts at the same Y as main. Pragmatic, isolated to the route, doesn't fight Polaris's slot model. Risk: tabs row divider only visually spans main, not the full content width — the line stops before aside. That looks worse than the current state for Lucas's "tabs should touch aside" framing.
    • Option F2 — Tabs row spans both columns. Render PageTabs with a CSS rule that extends its width to cover both main AND aside columns (negative right-margin equivalent to aside-column-width + gap, or absolute positioning across the full content area). Aside then sits BELOW the tabs row in document flow. Closest to Lucas's "tabs should touch aside" intent — the divider visually spans full width. Risk: depends on Polaris's exact aside-column width and grid gap, which could shift in future Polaris releases.
    • Option F3 — Custom page-body layout. Stop using slot="aside". Build our own two-column grid below PageTabs as a regular React component. Cleanest long-term — no Polaris-internals coupling. Risk: bigger refactor, every page with aside today (Brand, Affiliates, Storytelling, Retail Sales, Local Delivery, etc.) migrates off slot="aside" to the new pattern. Out of Phase A scope.

    Recommendation: ship Option F2 now (CSS-only, low risk if Polaris aside width is stable, gives Lucas the "tabs touch aside" visual). Validate post-deploy. If F2 ends up brittle, escalate to F3 in a follow-up PR.
  • Brand-page heading. Stays as "Brand Assets" for now. Could harmonize to "Settings" later for tab-strip consistency — flagging but not changing in this PR.
  • Block title change. "Tone of voice — sources" → just "Tone of voice" per Lucas's r2 feedback. Cleaner, and the pills below the title make "sources" implicit anyway.
  • Routing for tone-sources — breadcrumb ruled out (2026-05-12). Initial plan was a breadcrumb row at the top of tone-sources, but Lucas pointed out we can't slot into Shopify's chrome — a breadcrumb rendered inside <s-page> would read as body content, not chrome. Lucas favors Option C: the Settings tab strip extends with "Tone of voice" as the active tab and "Brand" rendered in-trail (subdued + italic + "›" chevron after it). One row, Polaris-native, doubles as both nav AND breadcrumb-trail indicator.
