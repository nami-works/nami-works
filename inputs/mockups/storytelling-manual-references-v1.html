Manual references — full reframe (mockup v1)

Replaces the current cramped one-row "URL + Fetch + or + Choose file" UI with a deliberate 3-tier flow inside the Manual references accordion body: (1) A spacious drop-zone hosting a Polaris-style "Choose file" button + drag-to-upload affordance; (2) a separate URL paste row below; (3) a reference list per file/URL with file vs link icons, char count, age, Re-extract, and Delete. Native "Escolher arquivo" button is gone — replaced by a Polaris s-button that triggers a hidden <input type="file"> via ref. Upload progress shows inline as a banner strip (not a button spinner across both forms). Rejection banner is contextual to the upload, file input clears automatically.

What this mockup decides

  • Native browser file button retired. Replaced with Polaris s-button + hidden input pattern. "Escolher arquivo" no longer leaks into the UI.
  • File and URL inputs visually separated — they're sibling intake methods, not competing on one row. Each gets its own block.
  • Upload progress shown inline as a strip with file name + status + progress bar. Not a spinner on a button that confused merchants when both forms shared loading state.
  • Per-row errors — rejection banners stay in-context, dismissable, never block the dropzone.
  • 30MB cap surfaced upfront, oversize-PDF error has actionable guidance.

Decisions baked in

  • ✅ "Choose file" is a Polaris s-button that triggers a hidden <input type="file"> via ref. Native "Escolher arquivo" gone.
  • ✅ File + URL inputs visually separated. Drop zone for files (visual emphasis), URL row below as sibling.
  • ✅ Per-form loading state. Uploading a file does NOT spin the Fetch URL button. Fetching a URL does NOT disable the file Choose-file button.
  • ✅ Upload progress strip replaces "button spins forever" — explicit file name, status text, progress bar.
  • ✅ Rejection banner is contextual — sits above the dropzone, dismissable, doesn't block retry.
  • ✅ Native file input clears on rejection (the bug Lucas reported where "_manualGEbeauty_final.pdf" lingered).
  • ✅ Reference list shows file vs URL icons, char count, age. Re-extract only on files (URLs are re-fetched via a different action — same Re-extract pattern still applies).
  • ✅ 30MB cap surfaced upfront in dropzoneSub copy. PDF-over-24MB error has tactical remediation.

Deferred / open

  • Drag-and-drop event handlers — visual affordance is there but actual drag-drop listeners (dragenter / drop) are wired in v2.
  • Cancel button during upload — UI is here, but the AbortController plumbing through the action would need extra work. v1 ships with "page refresh = cancel."
  • URL re-extract — currently Re-extract button only on file rows. URL rows could re-fetch the URL with the same intent — flag for v2 unless Lucas wants it now.
  • Multi-file upload — v1 ships single-file. Multi-select dropzone is a follow-up.
