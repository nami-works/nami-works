Per-stop POD bucketing — mockup v2 (final)

Issue nami-works/cpg-labs#1 · blueprint §13.8. Backend introduces 4 buckets (clean / mixed / held / skip) and a new mark-stop-delivered endpoint. This mockup shows the UI surfaces that expose those states on the existing dispatched-route card and stops list, plus the surgical-fulfill modal and the held-bucket modal. Five product decisions already locked by Lucas (see notes below).

Locked decisions (from /product-manager pass)

  • Held bucket → blocking modal listing pending/unmatched stops; primary Link stops manually, secondary Retry now.
  • partialDelivery → persistent yellow banner on the dispatched-route card with Retry verification; auto-dismisses on success.
  • mark-stop-delivered notify → no email preview; loud modal copy; notify toggle defaults ON.
  • Idempotency → check fulfillment.displayStatus; no DB table.
  • Retry chain timing → synchronous in the same request.

Surfaces shown below

  • A. Dispatched-route card with bucket-state variants (clean / mixed / held / skip) and the partialDelivery banner.
  • B. Stop list with per-stop pills (Delivered / Failed / Pending / Unknown) and overflow ⋯ menu.
  • C. Mark-this-stop-delivered confirmation modal.
  • D. Held-bucket modal listing pending + unmatched stops.
  • E. Per-bucket toast / banner feedback.

Important context

  • Today the route card has no UI Mark-as-delivered button — the function is invoked entirely by cron + CLI. The bucket result therefore surfaces as a passive status on the card (badge + banner), not as a click response.
  • Per-stop pills + overflow ⋯ live inside the existing details-route-modal, which already lists the route's stops (order name, customer, address). They're additive to that table — no new modal required for the pill surface.
  • The held-bucket modal in panel D fires from a notification on the route card ("Hold for review · open"), not from clicking Mark-as-delivered (since there's no such button). Once the operator resolves it, the cron picks up the route on its next pass.

Resolved decisions

  • Pill placement → modal only. Per-stop pills live inside the existing details-route-modal. Route card stays dense; operator clicks Details to see per-stop state.
  • Held bucket → blocking modal listing pending/unmatched stops; primary Link stops manually, secondary Retry now.
  • partialDelivery → persistent yellow banner on the route card; auto-dismisses when retry resolves.
  • mark-stop-delivered notify → no email preview; loud modal copy; notify toggle defaults ON; idempotent re-run shows "already delivered" with notify toggle off by default.
  • Idempotency → check fulfillment.displayStatus; no DB table.
  • Retry chain timing → synchronous in the same request.

Out of scope on purpose

  • No new top-level Mark as delivered button on the page or route card. The cron + CLI path stays unchanged.
  • No new per-stop "Mark failed", "Re-dispatch", or "Edit address" actions. Only Mark this stop delivered for now (Beatriz path).
  • Held-modal "Link stops manually" UI is referenced but not designed in this pass — when a stop is unmatched the operator gets a button that opens a follow-up linker. That linker is a separate mockup if needed.
