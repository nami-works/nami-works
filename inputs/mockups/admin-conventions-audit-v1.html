The <s-button slot="back-action"> we shipped in PR #49 occupies a title-row band ABOVE both main and aside. The bug Lucas saw on /app/settings/brand: the main column gets pushed down by the back-action band while the aside column starts at the original Y — they no longer align.

Implementation note

  • Root cause: Polaris's <s-page> renders slot="back-action", heading, slot="primary-action" and slot="secondary-actions" in a single title row above the default-slot content. But our pages with main+aside layouts wrap each in a <s-section> direct child of <s-page>, with the aside getting slot="aside". The page chrome doesn't know how main and aside align — and the way we wrap the main today (often inside an extra <s-stack> or <div>) adds an extra margin-top that aside doesn't pay.
  • Convention to codify: on any main+aside page, both columns are direct children of <s-page> (or both inside the same wrapper). NO extra <s-stack gap="..."> wrapping ONLY the main. Validate with: open the page, open devtools, both <s-section> elements should have the same offsetTop.
  • Pages to audit & fix: Brand (the reported case), Storytelling Brief, Storytelling Review, Local Delivery, Footprint Expansion, Retail Sales, Affiliates Overview, Settings.

Issue 2 — Block padding tokens

CLAUDE.md says "4px spacing grid" but the actual padding tokens our blocks use today vary: 12px, 16px, 20px, 24px, all encountered in production. Proposing a 3-token scale with explicit use cases.

Proposed token scale

TokenValuePolaris equivalentUse caseExamples in code
--pad-tight 12px padding="tight" Aside cards, table cells, compact filter rows Route Manager cards in Local Delivery, Auto-assign accuracy block
--pad-base 16px padding="base" Standard <s-section> and main blocks Brand configuration block, KPI cards, default <s-box>
--pad-loose 20px padding="loose" Wide hero blocks, modal bodies, full-width feature blocks Program overview header on Affiliates, drilldown chart panels

Implementation note

  • The 3-token scale maps to Polaris's native padding="tight|base|loose" props on <s-box> and <s-section>. Prefer the prop, not custom CSS. Custom padding values fall outside the system and drift over time.
  • Codify in CLAUDE.md under "UI Patterns > Block padding": "Default to Polaris padding props. Use padding="tight" on aside cards and dense lists, padding="base" on main content blocks, padding="loose" on hero/feature blocks. Don't hardcode padding values in CSS modules."
  • Add a lint rule to ESLint config: warn on padding: [0-9]+px in app/routes/**/*.module.css with a comment override for justified exceptions (maps, modals).

Issue 4 — Block-title typography hierarchy

Implementation note

  • Hard rule: the block title is ALWAYS visually heavier than the text directly under it. If the heading style ends up subdued and the body ends up bold, the hierarchy is inverted → fix immediately.
  • The Brand-context block uses a custom green-tinted card — fine for the tone, but the heading inherits a smaller-than-body size from the CSS module. Specific fix on that block: bump heading to 14px/650 and pin the stat row to 13px/400/subdued.
  • Pages flagged for the same audit: Storytelling Brief (the reported case), any block using <s-text-block heading="…"> patterns, and the Local Delivery "Auto-assign accuracy" block (heading reads smaller than the percentage below it).

Issue 5 — Map marker emoji → Polaris-style SVG

Local Delivery map markers use emoji to express priority/status: 🟡 address-error, 🥕 / 🏆 / ⏰ / 🕐 for due-bucket, 🏬 for store. They sit inside HTML elements rendered via document.createElement inside Google Maps' AdvancedMarkerElement. CLAUDE.md bans emoji-as-icon. Swap to inline SVG with the same semantic mapping.

Proposed swap

Current Proposed (inline SVG, Polaris-style) Semantic meaning
🟡 → alert-triangle (currentColor: #d72c0d) Address validation failed
🥕 → flash (lightning bolt, color: due-bucket) Due today, high priority
🏆 → star-filled (color: due-bucket gold) Premium / featured
⏰ → clock (alarm clock) Due-window approaching
🕐 → clock (standard clock) Future due-window
🏬 → store (storefront) Pickup location pin

Implementation note

  • Map markers are rendered via document.createElement inside Google Maps' AdvancedMarkerElement. <s-icon> web components don't render reliably outside the Polaris React tree, so the cleanest path is inline SVG strings built via DOM API — same approach as app/components/tab-icons.tsx.
  • Refactor: a new app/utils/map-marker-icons.ts file exporting dueBucketIcon(bucket), addressErrorIcon(), storeIcon() — each returning a properly-sized SVG HTMLElement. Replace the existing dueBucketEmoji + inline emoji literals in app.local-delivery.tsx.
  • Colors are still semantic (red for error, gold for high priority, etc.) but driven by CSS variables that match the rest of the UI tokens — no hex literals.
  • Verify on real map at 100% zoom (markers shouldn't look pixelated).
