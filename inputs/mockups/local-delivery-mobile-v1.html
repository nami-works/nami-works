Local delivery — mobile-only rebuild · mockup v1

Parallel mobile route that reuses the existing desktop loader/action unchanged. The desktop route redirects clients with window.innerWidth < 768 to /app/local-delivery-mobile on mount (?desktop=1 is an escape hatch). Scope is dispatch-first: Optimize, Request quote, Request driver, Cancel delivery, Clear route, View live status. No manual tweaking (no add-to-route, unassign, reorder, or drag). Map is a secondary viewer. Address errors and shipment requests are actionable via Shopify admin deep-links (which work on mobile admin).

Changes vs current desktop (what's REMOVED on mobile)

  • Aside column — single-column feed instead of the desktop two-column layout with sticky right aside.
  • Fullscreen map — the overlay that spills past the iframe on phones. Map is a collapsible 320px viewer.
  • Orders table — replaced by a vertical card list. The 1060px min-width table doesn't compress.
  • All multi-select + drag — no selection checkboxes, no drag-to-reorder, no add-to-route flow. Optimize is the only way to assign.
  • 17 <s-modal>s — replaced by ~10 <BottomSheet> instances using a single primitive. <s-modal> mounts via App Bridge overlay and has been seen to spill past the iframe.
  • Desktop-only editors — Lalamove settings, special requests, address verification, integration log, map style, return pickup flow. Surfaced as "Open on desktop ↗" chips.

What stays the same

  • Loader + all 17 action intents (export { loader, action } from "./app.local-delivery").
  • Route coloring, Lalamove status mapping (mapLalamoveStatusToInternal), terminal-status helpers — duplicated locally (~40 lines) so the desktop file stays untouched.
  • i18n namespace local-delivery; new keys live under a mobile.* section.
  • Google Maps loader + options (gestureHandling: "greedy" already correct).

Design notes

  • Feed over tabs — Routes is the entry; Map and Orders are secondary. Tabs would bury the dispatch CTA behind a nav click.
  • One sheet primitive, many instances — BottomSheet lives in the route file; 10 sheet types share its backdrop/positioning/safe-area logic. Do NOT use <s-modal> (App Bridge overlay spills past the iframe on narrow viewports, same bug class as the fullscreen map).
  • Route card status mapping — dispatchedRoutes[id]?.status → mapLalamoveStatusToInternal → card variant. TERMINAL_DISPATCH_STATUSES freezes the card (delivered/failed/expired/rejected).
  • Polling cadence — 15 s when tab visible, paused when hidden (Page Visibility API). Desktop polls 5 s; mobile is slower to save battery. Flag in the Phase C deploy-queue entry.
  • Triage chips are real actions, not dead ends — Address errors and Shipment requests open a sheet that deep-links to order.adminOrderUrl. Shopify admin works on mobile, so the user can actually fix the address and re-Optimize.
  • Auto-optimize on load — desktop fires this automatically when unassigned orders appear. Mobile is EXPLICIT tap in v1 to avoid surprise progress bars on page entry.
  • Map is opt-in, not always-on — collapsed by default in Frame A (no routes to show). Auto-expands in Frame B once routes exist. Saves ~300 px of vertical for dispatch-first states.
  • Safe-area padding — all sheets use padding-bottom: calc(16px + env(safe-area-inset-bottom)) so the CTA row doesn't hide behind the iOS home-indicator bar in the Shopify admin iOS app.

Decisions (resolved 2026-04-21)

  • ✅ Auto-fire Optimize on load — Explicit tap. Less surprising, user controls spend. Opt-in via ?autoOptimize=1 later if needed.
  • ✅ Polling cadence during active dispatch — 15 s + visibility-pause (Page Visibility API stops polling when tab hidden). Battery-friendly, +10 s worst-case latency vs desktop.
  • ✅ Return pickups on mobile — Keep desktop-only in v1. Chip stays as "open on desktop ↗". Port to v2 if the deep-link pattern proves out for Address errors.
  • ✅ Clear route / Clear all placement — Per-card overflow ⋯ + top-right ⋯ for Clear all. Hidden behind the overflow button — protects in-transit routes from accidental taps.
  • 🔸 Overflow menu (top-right ⋯) contents — default: "View desktop version", "Refresh data", locale toggle. Revisit if more desktop-only features get flagged during implementation.
  • 🔸 Empty-state copy for "all locations" — default: show Optimize CTA disabled with inline helper text "Pick a specific location to optimize." Matches the failure path in handleOptimizeFleet.
