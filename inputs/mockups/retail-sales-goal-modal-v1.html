Retail sales — goal-modal restructure · mockup v1

Restructure the Retail sales page so the Goals tab is removed and becomes a Set monthly goals button on the Dashboard tab. The button opens a full-screen modal holding the existing Goals UI, cleaned up to match current conventions. This mockup is the full Retail sales dashboard end-to-end, plus the modal, plus an audit of convention drift found along the way.

Primary change

  • Tabs reduced from 3 → 2. Dashboard · Goals · Campaigns → Dashboard · Campaigns. Goals tab deleted; its UI moves into a modal.
  • New trigger: Manage goals button lives in the overview-strip header, right-aligned, next to the friendly period display. Always visible on the Dashboard tab. Label is "Manage goals" (not "Set monthly goals") because goals may already exist and the button still needs to surface — manage covers create/edit/delete uniformly.
  • Modal type: full-screen takeover (Option A). Opens over the whole page, dark backdrop, clear dismissal. No URL change — stays on /app/retail-sales.
  • Dismissal: ✕ close button top-right, Done button bottom-right, Esc key, and backdrop click all close the modal. Changes auto-save per-card (same behaviour as today) — no global Save/Cancel.

Convention drift found during audit (fixed in this mockup)

  • Goals tab header used the legacy .controlsRow / .controlsLeft / .controlsRight pattern — CSS itself labels it "legacy". The Month select renders with a visible Polaris internal label, inconsistent with the Dashboard's external-label filter bar. → Migrated to .periodBar + .filterControl + .filterLabel with labelAccessibilityVisibility="exclusive", matching the Dashboard pattern.
  • "Apply growth to all" button sat alone in its own flex row — violates the row-packing rule (same rule that flagged the Affiliate page Export CSV on 2026-04-17). → Packed onto the same row as the Month filter, right-aligned.
  • Goals edit form used native HTML <select> + <option> for Base period and Growth unit (%/BRL). Convention: "Use <s-option> inside <s-select>, not HTML <option>". → Swapped to Polaris web components.
  • Cancel button used variant="tertiary" (not a valid Polaris variant — renders inconsistently). → Use variant="secondary", matching the Button order rule.
  • KPI active state used border-color: #1f2d5a !important on a child <s-box> to force an outline through the web component's shadow DOM. Hack works but reads as a bug. Flagged only — not fixed in this pass. See Open questions.
  • Drilldown card padding is asymmetric (20px 24px 20px 12px) — the 12px on the left was to pull the y-axis flush with the card edge. OK visually, but the reason is non-obvious; worth a comment in the CSS. Flagged only.
