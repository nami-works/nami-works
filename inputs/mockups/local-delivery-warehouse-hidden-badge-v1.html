Local Delivery — Hidden warehouse badge (Fix #3)

When the includeWarehouse toggle is OFF at a specific location AND warehouse-method orders exist at that location, surface a clickable warning badge inviting the operator to enable the toggle. Mirrors the existing visible-state badge in the route-manager warnings row.

Notes — design decisions baked into v1

  • Visual treatment: identical to the existing visible-state badge — <s-badge tone="warning" icon="package">. Warning tone communicates "needs attention but not urgent" per the CLAUDE.md color-semantics table. No new design tokens.
  • Clickability: the badge is wrapped in a <span style={{cursor:"pointer"}} onClick={handleToggleIncludeWarehouse}> — matches the precedent set by the addressErrorOrders badge (L4837) and pendingReturnPickups badge (L4844), both of which are click-to-action today. One click flips the toggle ON and the badge converts to the visible-state badge on the same revalidation.
  • Copy: "N warehouse orders hidden" — parallels the existing visible-state copy "N warehouse orders" but with the past-participle "hidden" to communicate the inversion. pt-BR: "N pedidos de armazém ocultos".
  • Triggering signal: requires a warehouseOrdersHiddenCount from the loader. The current loader's GraphQL query filters by deliveryMethod:LOCAL when toggle is OFF, so warehouse-method orders aren't fetched at all. Loader change: when toggle is OFF, do a second small Shopify search (count-only via orders(query:..., first:1) with a pageInfo.hasNextPage tally is awkward — easier to widen the main fetch to deliveryMethod:all always, then split visible/hidden in the existing eligibility block). See Open Questions for the tradeoff.
  • Belt-and-braces, not blocker: the server-side dispatch-drift guard from c8b7fe1 already returns an actionable error if drift occurs. This badge is the proactive UI cue so operators never get to the error in the first place.

Open questions for Lucas

  • Loader-side count mechanic. Two options:
    • (a) When toggle is OFF, also count warehouse-method orders via the same eligibility pipeline. Requires duplicating ~50 lines of filter logic OR widening the main fetch to always include deliveryMethod:all and splitting visible/hidden post-fetch. Recommend this.
    • (b) Cheap heuristic: a separate Shopify orders(query:..., first:1) with a tag/method filter to check existence-only. Loses the count precision; the badge would say "warehouse orders hidden" without a number.
    Lean is (a) — the count adds information value ("40 hidden" tells the operator the scale of what they're missing). pt-BR copy depends on this too: with count = "40 pedidos de armazém ocultos"; without = "Pedidos de armazém ocultos".
  • Clickable vs. text-only. v1 ships clickable (mirrors addressErrors and returnPickups patterns). Alternative: text-only with the operator expected to flip the toggle themselves. Recommend clickable — it's a one-click affordance that immediately resolves the warning state.
  • Icon choice. Existing visible-state badge uses icon="package". Reusing the same icon makes the inversion obvious (same icon, opposite tone implication via the "hidden" copy). Alternative: icon="eye-slash" or icon="archive" to differentiate. Recommend stay on package for consistency.
  • Order in the badges row. Failed delivery → presale → address errors → return pickups → warehouse-visible currently. Should hidden-warehouse sit in the same slot as visible-warehouse (mutually exclusive in the same state column), or at the start/end of the row? Recommend same slot — they're never both visible at the same time, so the position is stable.
