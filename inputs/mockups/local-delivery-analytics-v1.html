Phase-2 decisions locked (gate passed 2026-05-10)

  • Q1 — Provocation copy: Variant B (teaser with estimated savings) ships in v1. Phase 3 must verify Intelipost permits speculative quoting on arbitrary historical orders before merging; if not, falls back to Variant A.
  • Q2 — Opt-in toggle: Lives in /app/settings under Local Delivery. Off by default for v1, on after GE Beauty validation.
  • Q3 — Headline default: C — Shipping P&L impact. Picker (⇅) lets merchant switch to A (Revenue retained) or B (Net cost delta).
  • Q4 — Override granularity: Variant A — flat warehouse cost per location + tax savings % per LD city. Per-zone × weight matrix deferred to v2 if A proves too coarse.
  • Q5 — Entry point: Button "View analytics" in the LD page header. Sub-route at /app/local-delivery/analytics.
  • Q6 — Partial-data rule: Show with disclaimer + footnote when coverage ≥ 80%. Below 80% triggers the "insufficient data" empty state.

Phase-3 follow-ups (carry into spec)

  • Verify Intelipost speculative-quote feasibility — required for Q1 Variant B in state #3. If the API rejects quotes for orders that weren't shipped via Intelipost, fall back to Variant A and document the constraint.
  • Headline picker (⇅) — implementation detail: persist the merchant's framing choice in LdAnalyticsConfig so they don't re-pick on every visit.
  • P&L formula edge cases — orders with R$ 0 LD charge (free-ship) still incur LD carrier cost. Math holds, but the per-order drilldown needs a "free-ship" badge to explain why customer-charged is zero.
  • WH counterfactual on free-ship orders — counterfactual rate is what Intelipost would have charged for that order, NOT zero. Free-ship is a merchant subsidy, not a carrier discount. Spec must make this distinction explicit in the loader.
