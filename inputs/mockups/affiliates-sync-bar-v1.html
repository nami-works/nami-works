Recommendation if deciding by feel: Option B for Affiliates specifically, because the merchant comes to this tab DURING a sync (to see what's running) and the bar should announce itself. Option A is the better default if we want a quiet, always-on indicator across many sections. If you want both, the rule could be "Option B for first-class long-running syncs the merchant initiates; Option A for background reconciles they didn't ask for." — but that's complexity. Pick one for everything.

Pattern reusability — apply to every in-app sync

  • Affiliates Overview (the case Lucas flagged) — Program overview section.
  • Retail Sales — top section ("Sales overview" or similar). Already has "Last synced" label; promote it to this pattern.
  • Footprint Expansion — Heatmap section. Ingest progress for the per-shop bucket compute.
  • Settings > Brand (proposed merge — see settings-brand-merged-v1.html) — Tone-of-voice sources block. Uses identical pattern, sized for its smaller block.
  • Local Delivery — Map block header. Lalamove status reconcile is silent today; surface it. Dispatch reconcile (3min) is also silent — surface "Last reconciled N min ago".
  • Storytelling > Brief — Brand context band (already does this; the green block in app.storytelling_.brief.tsx). Reuse the visual treatment.

Why "in-block" and not "page-top banner"

  • Banners pile up. Built for Shopify caps stacked banners at 1 per viewport. Sync state, error state, helper text, plan-gated state — all compete for that slot. In-block keeps each indicator local to what it affects.
  • Multi-section pages. Affiliates has 4 tabs; each tab's sync state is different. A page-top banner can't express "Overview synced, Attribution Queue stale".
  • Visual weight. A 2px line + a 6-line status row inside the card is quieter than a full <s-banner> at the top of the page — and quieter is correct because most of the time the sync is healthy and merchant attention should be on the data, not the plumbing.

Implementation note (integrations-engineer brief)

  • Each page's sync indicator reads from a per-feature meta table (AffiliateSyncMeta, SalesGoalsSyncMeta, ShopIngestMeta, ToneSourceMeta, etc.). Add 4 columns where missing: lastStartedAt, lastFinishedAt, lastError, progressCount/progressTotal.
  • State derivation (client-side):
    • If lastStartedAt > lastFinishedAt AND lastError IS NULL → State B (running)
    • Else if lastError IS NOT NULL AND lastFinishedAt < lastStartedAt → State D (error)
    • Else if now() - lastFinishedAt < 5min → State C (done just now)
    • Else if now() - lastFinishedAt < expected_interval × 2 → State A (idle, recent)
    • Else → State E (stale)
  • Polling: when in State B, client polls every 5s (extend the existing useRevalidator pattern). When stable, no polling.
  • "Refresh"/"Retry"/"Sync now" all POST to /api/cron/<feature>-sync with ?manual=1 — same endpoint as the cron, bypasses watermark check.
