Monday.com filters — mockup v1

Replaces the current "API key + comma-separated board IDs" inline form on the Monday.com source row with a phased flow that fetches the actual column schema from each connected board, lets the merchant pick which columns to use for filtering, then builds rules from real column values. Prevents the "we pulled all items including the rejected drafts" problem.

Phased flow at a glance

  • Phase A — Connect: paste API key + board IDs (same as today). Save → server hits Monday API, fetches each board's columns + group structure.
  • Phase B — Choose columns: shows what we found (e.g. "Status, Owner, Approved by, Date"). Merchant picks which columns CAN be used as filters.
  • Phase C — Build filter rules: per column, set a rule (Status = "Approved"; Group ≠ "Drafts"; etc.). Rules combine with AND; multiple rules per column combine with OR.
  • Phase D — Preview: shows how many items match the current rules. Save commits the filter config to BrandIntegrationConfig.

Decisions baked in

  • ✅ 4-phase tabbed flow inside the source-row accordion body (A: Connect · B: Choose columns · C: Filter rules · D: Preview & save).
  • ✅ Phase B introspects Monday's column schema via Monday API on Connect success, surfaces actual column names + value sets, lets the merchant tick which columns are filterable. No free-text "type the column name yourself".
  • ✅ text + long_text columns are always content sources (the merchant doesn't pick those — they're the WHAT we sample).
  • ✅ OR within a column, AND across columns. Simple, predictable. Lucas can request more sophisticated boolean logic in v2.
  • ✅ Phase D preview shows match count + sample items before save — confidence-builder.
  • ✅ Edit view is condensed — already-onboarded merchants get a summary, not the full 4-tab flow.

Deferred / open

  • Schema cache invalidation — when does the app re-fetch column schema? Currently: on Connect, on Re-fetch CTA, and weekly via cron. Worth confirming.
  • People / Date columns as filters — v1 shows them as "skip" by default. Real Monday boards have date-based filters too ("updated in last 30 days"); v2 should expose this.
  • Filter rule schema in BrandIntegrationConfig — needs a small extension to the encrypted config blob to store the rule array. Today the config has just { apiKey, boardIds }; needs { apiKey, boardIds, filters: [{column, op, values}] }. Backward-compatible (empty filters = sample everything).
  • Multiple boards with different schemas — v1 assumes shared column names across boards. If schemas diverge, surfaces a banner.
