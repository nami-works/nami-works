Local Delivery — map badge scannability vs. Google road labels (mockup v1)

At city zoom on the dark Shopify-native map style, Google's native road and district labels (RJ-101, RJ-104, BR-101, ZONA NORTE, CENTRO) sit at roughly the same visual weight as the order-number badges. Non-selected badges get lost in the road-label noise. This mockup proposes a discreet, on-brand fix: keep the existing badge color system entirely, and add (a) a subtle hairline + halo "lift" that the badge already half-does, and (b) a one-knob desaturation of the map's own label fill via the existing map-style JSON. No new colors, no size bump, no flashy halos.

Design intent

  • Stay neutral. Badges encode route assignment via tone pairing (already approved in ld-map-pills-polaris-v1) — that's the only color signal on the map. No new color is added.
  • Reduce competition, don't shout. The fix lowers Google's label saturation/opacity and lifts the badge a touch — equivalent of bringing the badge half a step forward and pushing the road labels half a step back. Net visual mass between the two changes; the badge wins.
  • Two independent levers. Map-style label damping (Option A) is a 1-line styler change; badge lift (Option B) is a CSS-only change. They compose (Option C). Lucas can pick the dose.
  • Selected (holographic) state is out of scope. Already the most salient thing on the map. Don't touch.
  • Light map style preserved. The lift uses inner-ring + halo opacity, not a fixed color, so it survives the light map style without bleeding white-on-white or black-on-black.

Light map parity check — Option C applied

The badge lift uses opacity-based hairlines (not fixed black or white), so the same rule survives a map-style swap to light without recompiling. The inner ring flips from 55% white on dark to 18% dark on light; the halo flips from 18% black on dark to 55% white on light. Both transitions are handled by the existing mapStyle state branch already in app.local-delivery.tsx.

Implementation surface (for the production step — DO NOT touch yet)

Where this lands when approved

  • Map style JSON (Option A). The mapStyle === "dark" branch in app/routes/app.local-delivery.tsx (the styler array passed to new Map(..., { styles })) gets two new entries: { featureType: "road", elementType: "labels.text.fill", stylers: [{ saturation: -60 }, { lightness: -15 }, { opacity: 0.55 }] } and { featureType: "administrative.locality", elementType: "labels.text.fill", stylers: [{ saturation: -50 }, { opacity: 0.62 }] }. Light style gets the inverse lightness sign.
  • Badge lift (Option B). The badgeStyle object built around line 1980 of app.local-delivery.tsx gets a new boxShadow stack and a zIndex assignment on the marker element. The hairline ring is an inset 0 0 0 1px rgba(255,255,255,.55) inside the existing boxShadow string, gated on map style for the dark-vs-light variant. No new CSS class — this is a DOM-inline style on the marker, same as today's pattern.
  • Selected guard. The if (isSelected) { ... } block at the same site skips the inner-ring + halo additions but still bumps zIndex to a higher value so selected always wins.
  • No new tokens. All opacity values are inline. If we want to promote them later, the natural place is CLAUDE.md → UI Tokens; deferred.
