Omnify admin home — mockup v1

First-pass design for app/routes/app._index.tsx when APP_IDENTITY=omnify. Today the route redirects merchants straight to /app/local-delivery, which means the app has no "home" and fails Shopify's Built for Shopify §4.2.3 (helpful homepage) check. This mockup replaces the redirect with a real landing page: setup status, performance metrics, jump-back-in, and recent activity. Rendered side-by-side in two states so we can validate both the first-run and steady-state experience before translating to Polaris components.

What changed vs current

  • Drop the /app/local-delivery redirect for the Omnify identity. The home becomes a real page so §4.2.3 can be satisfied.
  • Setup guide — driven by real database checks (Lalamove credentials present? at least one location configured? carrier service registered? auto-delivery cron on?). Dismiss button only enabled once all required steps are done. §4.2.2.
  • Four metrics cards — one per enabled feature surface (Local Delivery / Retail Sales / Footprint Expansion / Affiliates for Omnify; up to 6+ for the CPG Labs full identity). Driven by getNavItems() so the same template serves both identities. §4.2.3.
  • Per-card natural cadence — each metric carries its own time window (Today · MTD · Lifetime · Last 30d). No global range picker; each surface picks the cadence that makes sense for its job-to-be-done.
  • Jump back in — four primary entry points (mirrors IDENTITY_NAV.omnify). One primary CTA per card per Polaris guideline. Affiliates is intentionally surfaced via its metrics card (not jump-back-in) because it's not currently in the nav.
  • Recent activity — last 5 system events pulled from the same audit log the cron pipeline already writes. Read-only. Empty state for first-run.
  • Footer help — docs link, support email, "What's new" link. Composition recommended by Shopify Homepage Pattern.
  • Regression banner (post-dismissal) — once the setup guide is hidden, a thin tone="warning" banner re-appears only when a previously-completed step regresses (e.g. credentials revoked, location deleted). Click → deep-link to the offending setting. Never re-opens the full guide.

Compliance check (Built for Shopify)

  • §4.2.3 Helpful homepage — setup status (guide), performance metrics (3 cards), live activity (recent events). No purely-static content. ✓
  • §4.2.2 Helpful onboarding — concise 4-step guide, step descriptions justify each ask, "Hide setup guide" appears once complete, never re-opens automatically. ✓
  • §4.1.1 UX best practices — Polaris primitives only, 4px grid spacing, WCAG-AA contrast on every label, single primary action per card. ✓
  • §4.1.4 Use the nav menu — home is the entry point that s-app-nav's app-name link points at. Page does not duplicate nav links inside the body. ✓
  • One purpose per page — orient + jump-back-in. No editing, no settings here. ✓
  • Single-column layout — Shopify-recommended for homepages. ✓
  • Action labels — verb + noun ("Plan deliveries", "Connect Lalamove", "Track retail sales", "Find new locations"). ✓

Implementation notes (when this moves to React/Polaris)

  • Single unified loader, identity-aware. One app/routes/app._index.tsx serves both cpg-labs and omnify identities. Metric cards, jump cards, and setup steps render based on getNavItems() + per-feature data probes. Omnify gets 4 cards (LD · Retail · Footprint · Affiliates). CPG Labs full gets up to 6 (adds Merchandising · Storytelling, plus Goals/Helpers as pre-existing helper cards).
  • Loader fan-out. Wrap data fetches in Promise.allSettled; each failure degrades to that card's empty state — never blocks the page. Required probes: getSetupChecklistState(shop), plus per-enabled-feature: getDeliveryActivityToday(shop), getRetailSalesSummary(shop, monthMtd), getFootprintSummary(shop), getAffiliatesSummary(shop, last30d), plus getRecentActivity(shop, limit=5) and getRegressionStatus(shop) (returns the most-severe regressed step or null).
  • Per-card cadence is explicit. Each metric helper owns its own time window — no shared range. Local Delivery = today; Retail Sales = MTD; Footprint = lifetime; Affiliates = last 30 days. If we ever need a global range later, add it as a per-card override, not a top-level picker.
  • Setup checklist persists per-shop in a new OnboardingState Prisma row (shopId, dismissedAt, completedSteps). Step completion is re-derived from system state on each load — never user-claimed. Once dismissedAt is set, the full guide stays hidden; getRegressionStatus() independently computes whether to surface the warning banner.
  • Regression banner trigger. Only shown when dismissedAt IS NOT NULL AND a required step's current state evaluates false (credentials missing, no enabled location, carrier service deregistered). One banner at a time, severity-ordered. Dismiss is session-scoped only — banner re-appears next page-load if not yet fixed.
  • Recent activity reuses the audit log the cron pipeline already writes ([local-delivery], [retail-footprint:sync], [affiliates:cron], etc. from CLAUDE.md "Logging" — but as a structured table, not raw stdout). New thin EventLog table; existing services dual-write.
  • Mobile: at ≤1100px the metrics row goes 2x2; at ≤600px it stacks. Setup-guide steps stack the CTA below the body. Jump-back-in goes 1-column.
  • i18n: keys under app/i18n/locales/{en,pt-BR}/home.json. Existing keys from the current function-card home are reusable for jump-back-in titles.

Decisions resolved (2026-05-06)

  • ✅ Affiliates — added as 4th metric card. Surfaced on the home even though it's not in IDENTITY_NAV.omnify. Jump-back-in mirrors NAV exactly (4 cards), so Affiliates is reachable via its metric-card footer link only.
  • ✅ Identity scope — unified template, drives off enabled features. Same route for Omnify and CPG Labs full; metrics row scales 4 → 6+ as needed.
  • ✅ Setup regression — thin warning banner (shown in State B), never re-opens the full guide. Banner copy: "Setup needs attention — <reason> → Fix now".
  • ✅ Activity time range — per-card natural cadence (Today · MTD · Lifetime · Last 30d). No global picker.

Still open (flag for review when implementing)

  • Affiliates in IDENTITY_NAV.omnify? — separate question, but if we promote Affiliates to a first-class home metric, the next logical step is adding it to the nav. Out of scope for this mockup; flagged for follow-up.
