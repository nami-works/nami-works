As-built — Omnify embedded admin home (shipped 2026-05-06 · commit 5e68627)

Visual record of app/routes/app._index.tsx, the Shopify admin home rendered when a merchant selects the app name in the admin nav. Same route serves both APP_IDENTITY=omnify and APP_IDENTITY=cpg-labs; metric/jump cards are driven by getNavItems(). Built for Shopify §4.2.3-compliant. Two production states shown vertically (first-run and returning); two sections are visually faded out as deferred-to-v2.

Why the page looks the way it does

  • Single column, top-to-bottom. Shopify's homepage pattern recommends this for orientation pages — merchants scan, then click. No sidebars, no tabs.
  • Setup guide auto-hides when complete. No explicit dismiss button. Step state is re-derived from the database on every load (Lalamove credentials? location configured? customer sync run?). Once all four steps register as done, the guide simply doesn't render. The next-state design (a thin warning banner if something regresses) is staged below as a Deferred section — it requires a new OnboardingState.dismissedAt column to land.
  • Four metric cards, not three. Affiliates is a first-class home metric (not a jump-only entry) because the auto-sync-from-Shopify-discount-codes feature shipped 2026-05-05 and the home is the easiest place to surface attribution health. Affiliates was promoted to IDENTITY_NAV.omnify in the same commit (5 nav items, still under the BFS 7-cap).
  • Per-card cadence chip, not a global range picker. Each metric picks the window that makes sense for its job: Today (LD), May (MTD) for retail, Lifetime for footprint, Last 30d for affiliates. Scaling decision: if we ever need to compare ranges, do it per-card (drilldown), not by adding a top-level dropdown.
  • Verb + noun jump labels. "Plan deliveries", "Track retail sales", "Find new locations", "Manage affiliates", "Settings" — predictable on click, no jargon.
  • Footer points at real targets. Docs and changelog live on cpg-labs.io (Astro static site). Support is mailto:.

Compliance check (Built for Shopify) — as shipped

  • §4.2.3 Helpful homepage — setup status (guide), performance metrics (4 cards). No purely-static content. ✓
  • §4.2.2 Helpful onboarding — 4-step guide, descriptions justify each ask, auto-hides when complete (no manual dismiss). ✓
  • §4.1.1 UX best practices — Polaris primitives only (s-page, s-icon, native CSS Modules), 4px grid, WCAG-AA contrast, single primary action per card. ✓
  • §4.1.4 Use the nav menu — home is the entry point s-app-nav's app-name link points at. Page does not duplicate nav links inside the body (jump-back-in cards are entry points by design, not duplicates). ✓
  • One purpose per page — orient + jump-back-in. No editing, no settings. ✓
  • Single-column layout — Shopify-recommended for homepages. ✓
  • Action labels — verb + noun (Plan deliveries · Track retail sales · Find new locations · Manage affiliates). ✓

Where to find the code

  • Route + components — app/routes/app._index.tsx. Loader does 4 defensive Prisma probes wrapped in Promise.all; each metric returns null on error or no-data, which renders the card's empty state. Setup state derives from LalamoveShopCredential, LalamoveLocationConfig, RetailSyncMeta.
  • Styles — app/routes/app._index/styles.module.css. Tokens copied from CLAUDE.md "UI Tokens"; metrics row breakpoint is ≤1100px → 2 cols and ≤600px → 1 col.
  • Copy — app/i18n/locales/{en,pt-BR}/home.json. All visible strings are i18n keys; the mockup mirrors the English values verbatim.
  • Nav promotion — Affiliates added to IDENTITY_NAV.omnify in app/utils/app-identity.server.ts (5 nav items, still under the BFS 7-cap).
  • Polaris icons — names verified against @shopify/polaris-types: delivery, chart-histogram-growth, location, affiliate, discount, blog, settings, apps.

Roadmap — what the deferred sections need

  • Recent activity — new EventLog table (Prisma migration). Existing cron pipelines ([local-delivery], [retail-footprint:sync], [affiliates:cron]) dual-write structured rows alongside their stdout logging. Loader reads top-5 by createdAt DESC for the shop. Retention policy: TBD (90 days vs 1 year).
  • Regression warning banner — new OnboardingState.dismissedAt column. Banner only renders when dismissedAt IS NOT NULL AND a required step currently evaluates false. Click → deep-link to the offending setting. Dismiss is session-scoped only; banner re-appears next page-load if not yet fixed.
  • Dynamic state-aware page subheading — currently uses the static i18n string in both first-run and steady states. Future: copy variants like "Wednesday, May 6 · everything's running. Three routes already dispatched today." for steady-state, and welcome-state copy for first-run. Requires a small server-side computed subheadingVariant in the loader.
