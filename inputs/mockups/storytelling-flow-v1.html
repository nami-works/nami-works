Storytelling — end-to-end flow (mockup v1)

The full process for the iterative AI<>human blog-content system at /app/storytelling. Six scenes covering brand setup, brief authoring, AI generation, review & publish, weekly diff detection, and learning loop. Phases 1–5 already shipped (single tone string + manual diff trigger). This v1 captures the full target state including Phase 6 additions: multi-source tone ingestion + auto-trigger via weekly cron.

  • Six scenes, one merchant journey. Each scene below shows the UI sketch + inputs/outputs/triggers. Open questions sit at the bottom.

Inputs

Processing

Merchant edits draft in Shopify, promotes to active

Shopify admin · external to our app · happens between Stage C and E
External
Shopify admin · Online Store › Blog posts Outside Omnify
Skincare brasileira: o segredo da pele madura Hidden

Merchant edits the article body inside Shopify's native editor — fixes wording, restructures, adjusts CTAs, then changes visibility to "Visible". This editing is intentionally OUT of our app: merchants already trust Shopify's editor and don't want a parallel one. Their edits become our learning signal.

Inputs

  • Merchant's editorial judgment — what to keep, what to change.

Processing

  • Happens entirely in Shopify admin. App is unaware until Stage E.

Outputs

  • Updated article body in Shopify.
  • Optional: visibility flipped to "Visible" (storefront publish).

Trigger

  • External: merchant decides when to edit.
  • App detects the change in Stage E.

Inputs

  • All BlogPostDraft rows where shopifyArticleId IS NOT NULL.
  • Current Shopify article body (via Admin GraphQL).
  • Brand context for grounding the diff interpretation.

Processing

  • Per draft: refetch article, compute meaningful change, call Claude interpretDiff.
  • Skip drafts with existing pending diffs (idempotent).

Outputs

  • One BlogPostDiff row per changed draft, status pending_review.
  • Pending-diffs banner lights up at /app/storytelling.

Trigger

  • Auto: weekly Monday 09:00 (shop local time).
  • Manual fallback: "Check for updates" button stays on Stage F page.

What this mockup is asking you to confirm

  • Six-scene merchant journey makes sense end-to-end? 0 → A → B → C → D → E → F.
  • Stage 0 belongs in /app/brand-settings/ (under Brand settings as a tab) rather than under /app/storytelling/. Tone is brand-wide — feeds future surfaces (alt-text, product copy) too. Confirm this placement.
  • Stage A target UI — themes-based form rather than JSON textarea. Built under separate Track D branch when the tone work lands.
  • Stage E is auto-only via cron — no in-app rich editor. Merchant edits inside Shopify's native admin (which they trust) and the system catches up weekly.
  • Stages B/C/F shipped — sketched here for completeness. No new design work for those.
  • The loop closes via two channels: (1) explicit traits validated at Stage 0 (proactive), and (2) implicit edits validated at Stage F (reactive).
