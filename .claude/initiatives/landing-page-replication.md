## Why
Paid traffic converts poorly because ads (influencer transformation videos) land on packshot-first PDPs with no message match. The fix is a dedicated cold/warm-traffic LP per advertised product — and the GOAL of this initiative is making each new LP **fast and repeatable to spin up**, not a bespoke build every time. The reusable template (`page.landing-page.json`, fully metafield-driven) and the Primer Cachos reference LP are the *enabler* (done); the ongoing work is running the playbook below per product so the next LP is a page-duplicate + metafield-fill + banner-gen, with zero theme-code edits.

## The replication playbook (run this per new product)

### 0. Prereqs (one-time, store-wide — already done)
- Template `templates/page.landing-page.json` exists on the **published** theme (verify `role == main` first — see [[reference_gebeauty_theme_publish_role]]; today it's `181379236160`, but CheckCommerce can swap it).
- PAGE metafield **definitions** exist store-wide. Definitions are created ONCE; per product you only set VALUES. Theme rejects any dynamic source whose definition is missing (`422 "dynamic source does not exist"`).
- Theme-wide price-in-button lives in `snippets/buy-buttons.liquid` + `snippets/card-product.liquid` (`money_without_trailing_zeros`).

### 1. Create the page
- New Shopify page, assign template `landing-page`. **Keep it draft** until the publish gate.

### 3. Generate the Canva banner pair (reuse the product's existing ad creatives — don't design from scratch)
Principle: the LP hero must MATCH the running ad (message match), so the banners are built FROM the product's existing "criativos" Canva design, not new art. Concrete pipeline with the Canva MCP tools:

**3a. Locate source + pick the two pages.** Find the product's criativos design id (Primer Cachos = `DAHNDkU4KaU`; `search-designs` if unknown). `get-design-pages` → pick the mobile page (square/vertical, best-performing Meta copy) and its desktop counterpart. For Cachos desktop = mobile + 29 (mobile 7 → desktop 36). VERIFY per source — the offset is design-specific.

**3b. Duplicate as a focused `lp_banner` variant (ONLY the 2 pages).** `copy-design` keeping ONLY `[mobile, desktop]` (Cachos = `DAHOV9m8tLI`). Canva refuses to edit very large designs, so subset to the two pages first.

**3c. Adapt copy + strip the logo.** `get-design-content` → `start-editing-transaction` → `perform-editing-operations`: remove GE logo, reposition copy so the CTA lands on whitespace (LP overlays its own button), keep the winning Meta headline → `commit-editing-transaction`. Dims: desktop ~1200×480; mobile ~960×1200.

**3d. Export + push to Shopify + wire.** `export-design` (PNG) → `fileCreate` with `originalSource` = the Canva export URL (same trick as `_dup_problem_image.py`), poll `fileStatus` READY → `metafieldsSet` `banner_desktop`/`banner_mobile`. Cachos assets: `primer-cachos-lp-hero-desktop.png` (1200×480, 43786643341632), `primer-cachos-lp-hero-mobile.png` (960×1200, 43786643374400).

### 3e. Fallback: when the creative's composition fights the fixed CTA — extend the background (Magnific) + rebuild in Canva
The hero + close CTAs sit **bottom-right** (shared template `box_align`), which only works if the banner's bottom-right is clean space. Cachos is fine (model/product on the LEFT). But if a product's only creatives put the subject/product on the **RIGHT** with clean space on the LEFT (e.g. **Primer Liso** — all its PMAX/META creatives are one model-right shoot), the CTA lands on the product. Flipping the photo mirrors the product label (off-brand); no opposite-composition creative exists. Fix = **generatively extend the background** so the subject shifts to one side and clean space opens where the CTA lands, then **rebuild the banner in Canva**. **Do NOT re-render the copy in PIL** — MCP can't set Canva font-family and weight-guessing keeps missing (an Expanded *Demibold* PIL render was rejected as off-brand); the seed's own Canva text elements carry the exact brand font (**Expanded Bold** headline + **Mono** subhead — see [[project_gebeauty_design_system]]).

1. **Clean photo.** `copy-design` the banner page → `start-editing-transaction` → delete the text elements → `commit` → `export-design` PNG = the text-free product/model shot.
2. **Magnific extend** (mirror of the Mist recipe, `gebeauty/imagery/body-hair-mist/mist-magnific-prompts.md`). `creations_upload_image`(public URL of the clean photo) → `images_generate` mode `imagen-nano-banana-2` (Nano Banana Pro), `references=[{type:image}]`, `aspectRatio` wide (`21:9`), `resolution:2k`, `count:3`. Prompt: *"Zoom out and uncrop this exact photo into a wider frame by extending mainly to the [RIGHT], as if the camera pulled back. Keep the [subject], hand and product with its label/printed text exactly as they are in the [LEFT] ~50%. The newly revealed area must be mostly EMPTY negative space: the same plain smooth grey studio seamless background, lots of open room for copy. Do NOT add new people/products/text/objects; ONE continuous backdrop; no second surface/horizon/shadow edge; same lighting."* Pick the best; crop to the banner ratio (1200×480 desktop).
3. **Rebuild in Canva** (reuse the seed text elements = exact font): upload the extended image to Shopify Files (temp) → `upload-asset-from-url` into Canva → in the design that still holds the seed text (the resized 1200×480 desktop copy; Liso = `DAHOXsZr5LU`): `resize_element` the bg element to 1200×480 + `position_element` (0,0) + `update_fill` with the extended asset (full-bleed), then `position_element` the headline + subhead onto the now-clean side → `commit`. Delete the temp Shopify file (`fileDelete`).
4. **Export + wire** as in 3d. Liso result: model-left / copy-right / CTA on clean grey, label intact — `banner_desktop` = MediaImage `43792372105536`.

Deterministic (non-generative) canvas extends work for plain/uniform backgrounds too: `gebeauty/scripts/extend_canvas.py` (bottom/left sides only).

### 4. Publish gate (approval-gated, Lucas)
Message-match check vs live ad, Core Web Vitals (LCP<2.5s / CLS<0.1), Pixel+CAPI+UTM firing, then publish + repoint ad destinations.

## Multi-product LP template (reusable) — `templates/page.guia-boosters.json`

The sibling of the single-product template above, for a **line/collection of N products on one page** (built + proven on Boosters, 2026-07-09). Fully page-metafield-driven — same promise: a new multi-product LP is duplicate-page + fill-metafields + point-products, **zero theme-code edits**.

**Key reuse principle:** all product-set LPs can share this ONE template suffix (`guia-boosters`) — the section *structure* is shared, per-page *content* comes from `page.metafields`. Assign the same template to each new page; do NOT clone the template per LP (only clone if you need a structurally different layout). The suffix name is cosmetic (booster-flavored but generic in function).

### Section order
`hero(slideshow)` → `oquesao(boosters-oquesao — intro pills)` → `trust(icons-with-title, STATIC brand icons)` → `punchline(boosters-headline)` → `card_1..8(featured-product — empty slots self-hide)` → `promo(lp-promo-icones)` → `kits_boosters(featured-collection — bundles)` → `faq`.

### Custom theme sections (created for this template)
- **`boosters-oquesao`** — heading + up to 8 "ponto" pills (`inline_richtext`, auto-fits 4-up desktop / 2×2 mobile via computed `--dcols`/`--mcols`, blank pills skipped, text wrapped in a span). Display name "LP · destaques (pílulas)".
- **`boosters-headline`** — centered H2. "LP · título de seção".
- **`lp-promo-icones`** — objection/reassurance strip; renders `page.metafields.custom.promo_icones` (list of `icones` metaobjects) and falls back to a default trio (`compra-segura`/`compre-em-ate-6-x-sem-juros`/`oferta-frete`) when the page metafield is empty. "LP · ícones de objeção".

### Page-metafield register (custom.*)
| Key | Type | Feeds |
|---|---|---|
| `banner_desktop` / `banner_mobile` | file_reference | hero slideshow images |
| `intro_titulo` | single_line | intro section heading |
| `intro_ponto_1..4` (up to 8) | single_line (inline `<strong>` ok) | intro pills |
| `cards_titulo` | single_line | heading above the product cards |
| `produto_em_destaque_1..8` | product_reference | each drives one card (title/price/buy/image/benefits/stars/tabs all cascade); slots 6-8 empty = hidden |
| `promo_icones` | list.metaobject_reference → `icones` | objection strip (optional; default trio if empty) |
| `faq_titulo` | single_line | faq heading |
| `faq_1..4_pergunta` | single_line | faq questions |
| `faq_1..4_resposta` | rich_text_field | faq answers (bind `\| metafield_tag`) |
| `colecao_titulo` | single_line (inline `<strong>` ok) | bundles section title |
| `colecao_descricao` | rich_text_field | bundles section subhead/caption |
| `colecao_em_destaque_1` | collection_reference | bundles collection |
| `tab_1_label` / `tab_2_label` / `tab_3_label` | single_line | card tab labels (per-LP; default `como usar`/`resultados`/`saiba mais`) |

**Tab labels are page-driven** (added 2026-07-09): the acc block renders `{{ page.metafields.custom.tab_1_label.value \| default: 'como usar' }}` etc., so each LP labels its own tabs while the underlying fields stay `passo_a_passo`/`resultado`/`o_que_e`. Boosters set theirs to `como combinar`/`resultado`/`saiba mais`; simpler products use the `como usar` default. The TAB CONTENT still rides the product's `descricao_longa_com_abas` metaobject.

**Conditional "itens do kit" tab** (added 2026-07-25, for kit/bundle products): each card's `acc` block prepends a hardcoded-label **"itens do kit"** tab (`data-tab="tabkit"`) as the FIRST/active tab, gated on `section.settings.product.metafields.custom.descricao_longa_com_abas.value.itens_do_kit != blank`. It loops that `list.product_reference` and renders each component as a `.gbkit__row` (thumb + title, links to the product). When `itens_do_kit` is unset (non-kit products: boosters, travel-size), nothing renders and tab1 stays active — shared template stays safe. Active state is Liquid-conditional (tabkit active when present; tab1 active only when kit absent); the tab-switch JS handles `tabkit` with no JS change (it toggles by `data-tab`→`data-content`). Verified: boosters/travel unchanged, wash bundles show the kit tab first.

**Bundles caption is page-defined on purpose** (2026-07-09, Lucas): the same "destaque" collection is reused across LPs for AOV pushes under different framings, so the LP owns the copy while the collection is just store-managed hygiene. Mechanism: featured-collection `show_description: false` → the section renders `{{ section.settings.description }}` (bound to `colecao_descricao` via `| metafield_tag`), NOT the collection's own description. (`show_description:true` would instead render `collection.description` and ignore the setting — that's the alternative if you ever want the collection to own the copy.)

### Product-metafields that ride each card for free (via `section.settings.product`)

## Dynamic-source rules (hard-won) — see [[reference_shopify_dynamic_sources]]
- **Single-hop only** from `page` (`{{ page.metafields.custom.X.value }}`); page→product→field double-hop is rejected. BUT inside a featured-product section, `section.settings.product.metafields…` IS a valid single-hop (how benefits are seeded).
- **Definition required** (ownerType PAGE) or 422 "dynamic source does not exist".
- **Binding syntax:** image/resource refs + text/inline_richtext → `.value`; richtext → `| metafield_tag` (bypasses the `<p>/<ul>/<ol>/<h*>` literal validation); rich_text_field values must be the JSON AST, not HTML.

## PDP-vs-LP destination A/B — the growth validation (design agreed 2026-07-04, BUILD DEFERRED)
**Framing (Lucas's):** NOT product-vs-product. Two parallel, independent tests — each product tests its OWN hypothesis: *does its LP convert better than its default PDP?* Leverage existing ads (reuse proven creatives; build no new creatives).

**Design (per product — Cachos + Liso in parallel):**
- Meta **native A/B Test (Experiments)**, single variable = **destination URL**. Arm A (control) = PDP `/products/…`; Arm B (variant) = LP `/pages/…`. 50/50, no overlap. Launched FROM the campaign (Meta duplicates arm B + swaps URL) — NOT two ads in one ad set (delivery bias makes that invalid).
- Matched across arms: same **top-3 proven creatives**, Advantage+ audience, CBO, matched daily budget (recommended **R$150/day/product**), Purchase optimization.
- **Controlled parallel test** — do NOT edit existing winning ads to point at the LP (resets learning, dirties the read). Always-on keeps running to PDP.
- Both products launch same day; **don't touch during learning** (~50 purchases/arm); read at ~50+ purchases/arm (~**2–3 weeks**).
- Decision metric: **CVR + CPA + ROAS** (weight CPA — Cachos R$149 vs Liso R$139 flatters Cachos ROAS ~7%).
- Roll out per product independently: LP wins → repoint that product's always-on ads (incl. MISTO) to the LP; else stay PDP.

**Prereqs before launch:** verify Purchase pixel + CAPI fire for LP-origin sessions (checkout fires regardless of landing page, but confirm once); add UTMs (`utm_campaign=teste-lp-cachos`/`-liso`); stable window; freeze LPs.
